## Repeatable qualification process (AI Lab)

REGISTERED -> artifact_present -> identity_verified -> rights_and_runtime_verified -> technically_qualified -> task_screened -> finalist_for_bounded_comparison -> evaluated -> retain/revise/reject/defer. No auto-promotion and no architecture selection from popularity.

1. Discover from publisher cards, quantizer repo and runtime docs; record exact repo/revision/file, release/license and intended task, support limits and hypotheses. Once downloaded, inventory local actual files + SHA-256, size/mtime, GGUF header/arch/quant, tokenizer/chat template hash, provenance/license and allowed data use; cross-check published file digest/revision if available. Missing rights or identity blocks relevant dispatch.
2. Verify runtime version/backend, structured output or task-native format, tokenizer, actual context/template, VRAM/Windows+WSL RAM/offload and observed performance under bounded E2.3 preflight principles. Check active workload; no unattended upgrade/unload. If runtime changes, separate runtime arm or rerun matched comparator under explicitly frozen new version before diagnostic comparison; no mixed silent confound. Test for silent wrong outputs on unusual kernels; incompatible artifact deferred, not force-loaded.
3. Separate task-specific screen from E3 full comparison. Proposed future bounded tranche max 3 new artifacts of a **single task class**, max 2 synthetic or exposed source cases/artifact (same fixed cases and incumbent paired), max 3 physical completion POSTs/cell incl retries, 180s/cell, max 24 generation POSTs including incumbent and max 30 active minutes including setup, plus separately accounted technical preflight (E2.3-style max 2 probes/artifact, 180s/artifact; overall active max 45min including preflight, whichever cap first). For embedding use same fixed queries/docs, max 24 embedding HTTP dispatches instead of generation; freeze query relevance/duplicate judgment and corpus before retrieval. No call authorized by this registration; separate scoped manifest, task-specific metrics and rights review first. Stop if caps/identity/privacy breached; no automatic next tranche. Do not spend all budgets simply because available. Include all attempted and unattempted cells. No B5 source used as unseen, no new acquisition.
4. Semantic screen: compact same-task contract, one English dense and one Persian compound-qualification case (D1/D5 proposed, exact references from E2.3); compare incumbent under same settings and E2.4 semantic/coverage gates; no screen-only superiority or deployment claim. Translation: same original passages/context and target, compare E2B, score meaningful terminology, names/numbers/negation/modality/OR/duty boundaries, omissions/additions and end-to-end cost; pure text translation needs no JSON duty taxonomy, do not reuse semantic score as translation score. Retrieval: task-specific Recall@k/precision@k, near-duplicate group leakage and latency vs lexical+existing embeddings; no canonical merge or fact promotion. Large reasoning: conditional separate budget/latency comparison, no automatically inflated cap.
5. E2.5 explicitly assess whether any new model should replace/add a preregistered research arm before first diagnostic outputs. By default retain E2.3 M0/M1, M2 technical fallback only; no expanded 47-cell grid. New downloads are not execution dependencies. If new model needs additional screening, select separately after E3 runner/guards and E2.4 rubric ready; predeclare inputs, costs, candidate versions and decision. If discovery happens after diagnostic results, separate new experiment ID/manifest, preserve prior results. Broader model/translation/retrieval tracks remain registered even if E2.5 defers.

# R05 A2 targeted security review notes

A2's diagnostic payloads are local and non-authoritative, but should not be described as encrypted or secret-free. Failed model content may contain employer/source text and locally supplied instructions. Normal attempt rows use application-authored error categories for v21; existing historical attempts may still have unsanitized legacy error strings, so the diagnostics CLI omits those fields. The raw CLI option is deliberately explicit and should be run only in a private terminal; terminal scrollback and shell redirection are outside database retention. SQLite diagnostic-store cleanup uses `secure_delete`, with finite per-payload/count/age limits, but backup files and SQLite WAL/checkpoint behavior are not equivalent to a secure-erasure guarantee. The read-only CLI does not physically prune; a subsequent diagnostic-store read/write does. No private response material is routed to the public corpus, but a full export/log review should accompany any release. No remote or authenticated web diagnostic endpoint is implemented by A2.

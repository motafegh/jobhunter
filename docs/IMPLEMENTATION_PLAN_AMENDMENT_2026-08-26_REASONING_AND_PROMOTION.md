# Implementation Plan Amendment — Phase-2 Reasoning and Promotion

**Status:** CONTROLLING IMPLEMENTATION-PLAN AMENDMENT  
**Date:** 2026-08-26  
**Amends:** `docs/IMPLEMENTATION_PLAN.md` for Phase 2 and later analytical implementation  
**Governed by:** `docs/UTILITY_EPISTEMIC_AUTHORITY_AND_REASONING_POLICY.md`

---

## 1. Purpose

This amendment prevents Phase-2 delivery from applying Phase-1/P2.1 promotion-grade acceptance to every analytical output.

The accepted Phase-1 and P2.1 contracts remain unchanged.

The implementation rule going forward is:

> **build trustworthy substrate strongly; allow bounded analytical reasoning early; require stronger review when a result is promoted into reusable authority.**

---

## 2. Delivery rule update

Add these permanent rules to the implementation discipline:

- optimize each vertical increment for a real reduction in user reading/decision effort;
- deterministic logic remains deterministic where the problem itself is deterministic;
- do not force semantic/model interpretation into deterministic equivalence merely to make tests simpler;
- distinguish candidate/generated intelligence from promoted reusable authority;
- scale validation effort to blast radius and downstream reuse;
- treat interpretive uncertainty as confidence/alternatives/unknowns unless an integrity invariant is violated;
- avoid duplicate reruns/manual gates that do not materially increase confidence in a consequential boundary;
- do not require exhaustive canonical mapping before delivering bounded job-level intelligence.

---

## 3. Acceptance tiers

### Tier A — integrity/persistence acceptance

Strongest requirements.

Applies to:

- source truth;
- artifact/dependency/currentness identity;
- persistence and migrations;
- canonical registry mutations;
- privacy/publication boundaries;
- deterministic aggregates;
- promoted reusable semantic entities/relations.

Typical acceptance:

- deterministic tests;
- invariants;
- idempotency/history checks;
- representative live/local validation where material;
- human semantic review where promotion contract requires it.

### Tier B — promoted semantic acceptance

Applies when an analytical concept becomes reusable authority, e.g. accepted responsibility family or role archetype.

Typical acceptance:

- supporting jobs/evidence;
- definition and boundaries;
- provenance;
- ambiguity/unmapped behavior;
- representative semantic review;
- downstream-use justification.

Do not require exhaustive corpus coverage unless the promoted claim itself requires it.

### Tier C — bounded analytical interpretation

Applies to low-blast-radius, regenerable job-level or exploratory intelligence.

Examples:

- work-composition summary;
- candidate family/archetype;
- comparative synthesis;
- strongly work-implied expectation;
- exploratory pattern.

Typical acceptance:

- correct authority labels;
- support/reason traceability;
- no source-fact fabrication;
- sensible confidence/uncertainty behavior;
- useful UX;
- targeted qualitative/regression checks rather than promotion-grade ceremony.

Tier C output may be useful without becoming Tier B authority.

## 4. P2.2 implementation order

The next focused Phase-2 plan must design P2.2 in this order:

```text
P2.2A — responsibility/work intelligence contract
- exact factual input boundary
- candidate vs promoted states
- fast work-composition interpretation
- uncertainty/confidence semantics
- promotion rules

P2.2B — bounded responsibility/deliverable normalization
- add reviewed reusable mappings where downstream value justifies them
- do not normalize every claim by default

P2.2C — responsibility-family layer
- candidate families may be generated before promotion
- promoted family entities/memberships use stronger review

P2.2D — role-archetype intelligence
- job-level candidate archetype/work composition may exist early
- stable archetype promotion requires stronger cross-job/employer support
```

The focused P2.2 plan may adjust increment labels after design, but it must preserve these authority distinctions.

---

## 5. P2.2 definition of done

P2.2 should not be judged solely by taxonomy completeness.

A successful P2.2 must prove that the user can understand responsibility/work structure faster than manual reading while retaining inspectable evidence and uncertainty.

At minimum, acceptance should demonstrate:

- one or more real jobs produce useful work/responsibility interpretation;
- source facts remain distinguishable from JobHunter interpretation;
- ambiguous/multi-family cases do not force false certainty;
- candidate intelligence can exist without canonical promotion;
- promoted reusable responsibility/family/archetype state, if created, has stronger review/provenance;
- browser/CLI or whichever normal user surface is in scope makes the distinction understandable;
- quality gates cover implementation/integrity without demanding deterministic wording from semantic reasoning.

---

## 6. P2.3/P2.4 consequence

P2.3 job-capability profiles may use explicit and strongly work-implied interpretation without first promoting every implication into universal taxonomy truth.

P2.4 canonical Market v2 still aggregates promoted/current canonical state for stable metrics. Exploratory non-promoted patterns must remain separately labeled and must not silently enter stable market statistics.

---

## 7. Non-goals

This amendment does not authorize:

- model-generated employer facts;
- automatic canonical promotion;
- fixed title-first archetypes;
- opaque scoring;
- unqualified broad-market claims from tiny samples;
- personal readiness before its reviewed evidence domain;
- bypassing privacy, source, persistence, or provenance invariants.
